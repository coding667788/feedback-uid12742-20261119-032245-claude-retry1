# 会话日志配对与歧义覆盖

为合成安全审计日志匹配会话两端。给定两个约定端点的事件流、分段时间校准与
连接键，求出**最大匹配数 → 最小总代价 → 字典序最小代表解**三层最优目标，
并对每条候选边给出它在所有最优解中的出现情况（`all`/`some`/`none`），
对每个未匹配事件判断它能否在别的同优解中被匹配。

仅使用 Python 3.12 标准库、纯 CPU、离线运行，无任何第三方依赖。

## 2. 运行方式

在项目根目录执行：

```bash

重新生成输入（确定性，固定随机种子，内容可重放）：

```

## 3. 输入结构（cases.json）

顶层为 `{"schema_version": 1, "cases": [ ... ]}`，每个用例：

```json
{
  "name": "c01_full_ambiguity",
  "endpoint_a": "C",
  "endpoint_b": "S",
  "threshold": 5,
  "calibration": {
    "C": [
      {"local_lo": 0, "local_hi": 600, "offset_lo": 10, "offset_hi": 10},
      {"local_lo": 600, "local_hi": 1200, "offset_lo": -10, "offset_hi": -10}
    ],
    "S": [ {"local_lo": 0, "local_hi": 1200, "offset_lo": 0, "offset_hi": 0} ]
  },
  "events": [
    {"event_id": "L1", "join_key": "k", "endpoint": "C",
     "direction": 0, "local_time": 599}
  ]
}
```

字段约定：

| 字段 | 含义 |
|---|---|
| `endpoint_a` / `endpoint_b` | 约定的两个端点名；配对只在这两端之间发生 |
| `threshold` | 非负整数；可接受时间差，比较采用 **小于或等于（<=）** |
| `calibration[ep]` | 该端点的分段校准，按本地时间**左闭右开** `[local_lo, local_hi)` |
| `offset_lo` / `offset_hi` | 该段偏移不确定区间的两个整数端点（闭区间），须 `offset_lo <= offset_hi` |
| `event_id` | 用例内唯一的非空字符串，重复即结构错误 |
| `join_key` | 连接键；同一键内才可能配对，每键事件数上限 **120** |
| `endpoint` | 必须是两个约定端点之一 |
| `direction` | 只允许 `0` 或 `1`；**互补即取值不同**（0↔1），相同方向不连边 |
| `local_time` | 整数本地时刻，必须被某段 `[local_lo, local_hi)` 覆盖 |

### 时间到统一时刻区间的映射

事件本地时刻 `t` 落入校准段 `[lo, hi)` 后，其统一时刻为闭区间

```
[t + offset_lo, t + offset_hi]
```

校准段必须**严格首尾相接**：相邻段要求前段 `local_hi ==` 后段 `local_lo`，
否则报缺口（gap）或重叠（overlap）。左闭右开意味着边界时刻 `local_hi`
属于后一段而非前一段（见 `c04_offset_switch`：本地 599 走段 1、600 走段 2）。

### 连边与代价

同一 `join_key` 内，端点 A 的事件（左）与端点 B 的事件（右）之间，当且仅当

1. 方向互补（`direction` 不同）；
2. 两个统一时刻闭区间的**最小绝对距离** `d <= threshold`；

才建立候选边。区间距离定义为

```
d([a1,a2],[b1,b2]) = b1-a2  若 b1>a2；a1-b2 若 a1>b2；否则 0（相交/相切）
```

边的代价就是该距离（非负整数），区间相切距离为 0。

## 4. 三层优化目标与歧义语义

按字典序依次优化：

1. **最大匹配数**：每个事件至多参与一条边，最大化配对数；
2. **最小总代价**：在所有最大基数匹配中最小化边代价之和；
3. **字典序最小代表**：在同时满足前两层的解中，把规范事件 ID 对
   `(left_event_id, right_event_id)` 列表按字典序取最小者。

候选边歧义标签（针对满足前两层目标的全部最优解）：

| 标签 | 含义 |
|---|---|
| `all` | 出现在**每一个**最优解中（强制边） |
| `some` | 出现在**部分但非全部**最优解中 |
| `none` | 候选有效（满足阈值/方向/键），但**不在任何**最优解中 |

未匹配事件的 `coverable_elsewhere`：该事件在代表解中未配对，但是否存在
另一个同优解（同基数、同最小费用）使它被配对。

## 5. 算法（大样例禁止枚举全部最优配对）

- **前两层**：二分图最小费用最大流。源点→左点、右点→汇点容量 1、费用 0；
  候选边容量 1、费用为区间距离。逐次最短路 + Dijkstra 势函数求最大流量下
  的最小费用。
- **歧义判定**：取最终势函数下**残量为正且缩减成本为 0** 的弧构造残量子图
  G0，Tarjan 求强连通分量、缩点 DAG 上用整数位掩码求 SCC 可达性。基于最优流
  互补松弛：
  - 已用边 `(l,r)`：G0 中 `l` 不可达 `r` ⇒ `all`，否则 `some`；
  - 未用边：前向缩减成本为 0 且 G0 中 `r` 可达 `l` ⇒ `some`，否则 `none`。
- **未匹配可覆盖性**（Dulmage–Mendelsohn 分解）：在零缩减成本二分图 H0
  （即标签 `all`/`some` 边构成的图，代表流是其一个最大基数匹配）上，未匹配
  右点可覆盖 ⇔ 存在某左点经一条**非匹配** H0 边指向它（该左点空闲即直接增广，
  已匹配则换出其当前配对，因两者同为 H0 最大基数匹配，换后仍最优）；未匹配
  左点对称。该判据同时涵盖零成本增广路与交替环，且不会把仅有正费用边的孤立
  事件误判为可覆盖。
- **字典序代表**：属于至少一个最优解的边（标签 `all`/`some`）构成二分图 H0，
  其最大基数匹配与全部最优匹配一一对应。沿规范 ID 对顺序逐条试探强制纳入，
  每次用 Hopcroft–Karp 在剔除两端后的子图上重算最大基数做可行性判定
  （固定-重算，多项式复杂度），可行即锁定。整个过程不枚举任何最优配对集合。

复杂度：单组左右各 ≤120 事件，MCMF 为 O(F·E·log V)，SCC/可达性 O(V+E)，
固定-重算 O(E) 次 Hopcroft–Karp，均为多项式，实测大样例毫秒级完成。

## 6. 错误码

结构错误按用例收集，不阻断其他用例；出错用例 `status` 为
`structural_error`，正常用例为 `ok`。

| 错误码 | 触发条件 |
|---|---|
| `E_MALFORMED_INPUT` | 类型/字段缺失/取值非法；布尔冒充整数；`local_lo >= local_hi`；`offset_lo > offset_hi`；阈值非非负整数；方向非 0/1；顶层不是含 `cases` 数组的对象；JSON 无法解析 |
| `E_DUPLICATE_EVENT_ID` | 同一用例内事件 ID 重复 |
| `E_CALIBRATION_GAP` | 校准段之间存在缺口（前段 `hi` < 后段 `lo`），或约定端点完全没有校准段 |
| `E_CALIBRATION_OVERLAP` | 校准段相互重叠（后段 `lo` < 前段 `hi`） |
| `E_EVENT_OUTSIDE_CALIBRATION` | 事件本地时刻不被任何左闭右开校准段覆盖 |
| `E_UNKNOWN_ENDPOINT` | 事件或校准引用了两个约定端点之外的端点 |
| `E_GROUP_LIMIT` | 同一连接键的事件数超过 120 |

## 7. 边界示例（cases.json 内置）

| 用例 | 覆盖点 |
|---|---|
| `c01_full_ambiguity` | 2x2 零成本完全图，四条边全 `some`，代表解字典序最小 |
| `c02_none_edge` | 最优值唯一但存在候选有效却 `none` 的交叉边（费用 4 但不在最优解） |
| `c03_threshold_boundary` | 距离恰等于阈值（`<=` 生效）；偏移不确定区间；费用为正的最优匹配 |
| `c04_offset_switch` | 分段偏移切换 + 左闭右开边界（599/600 分属不同段） |
| `c05_unmatchable` | 同方向过滤 + 超阈值，未匹配事件 `coverable_elsewhere=false` |
| `c06_coverable_unmatched` | 代表解下未匹配但可在别的同优解被覆盖（`true`） |
| `c01_shuffled` | `c01` 的乱序输入副本，输出语义与原用例完全一致 |
| `fuzz_00..fuzz_23` | 固定种子随机小图，全部经独立枚举逐字段交叉验证 |
| `large_120x120` | 120 条/端、8 个连接键组；含偏移切换、`none` 边、`some` 歧义块、方向过滤、不可匹配事件 |
| `err_*`（9 个） | 每个结构错误码各至少一例 |

## 8. 测试与期望值来源

测试期望值**不从被测实现反推**，来自两类独立来源：

1. **独立枚举参考 `tests/ref_enum.py`**：不 import `solution` 任何模块，
   用回溯穷举 ≤8x8 小图的全部二分匹配，独立重算区间数学、连边、三层最优、
   字典序代表、`all/some/none` 标签与可覆盖性，再与引擎输出逐字段比对。
2. **硬编码断言 `tests/test_hardcoded.py`**：对手工用例在注释中给出人工推导
   （如 c02 中含交叉边的基数 2 匹配费用必为 8 > 0，故交叉边为 `none`）。
3. **大样例 `tests/test_large.py`**：期望值由样例生成约定独立给出
   （120 对时刻对齐 + 偏移一致 ⇒ 最大基数 120、最优费用 0），并独立重算代表
   解每条边的区间距离做一致性校验，同时断言 5 秒内完成以佐证未枚举。

## 9. 实测结果

环境：Windows 11 Pro，Python 3.12.8（原生），仅标准库、纯 CPU。

```
$ python -m unittest discover -s tests -v
...
Ran 21 tests in 0.044s

OK
```

- 21 个测试全部通过；其中独立枚举交叉验证覆盖 **31 个**合法小用例
  （手工 7 个 + 随机 24 个），全部字段一致。
- 开发期另用三个独立随机种子生成共 **1300 个** ≤8x8 随机小图，逐字段比对
  基数、费用、字典序代表、`all/some/none` 标签与未匹配可覆盖性，均与独立
  枚举零分歧；三类标签与“可在别处匹配”的情形都被实际命中。该随机验证可用
  固定种子在本地复现。
- `large_120x120`（120 条/端 + 注入事件，分 8 组）：
  最优匹配数 **120**、最优总费用 **0**，单次求解墙钟约 **0.006 秒**；
  全文档 41 个用例合计约 **0.015 秒**。
- 大样例标签分布包含 `all`、`some`（K1 的 2x2 歧义块 4 条）、
  `none`（K0 的 `S0_X` 等费用次优边）；所有 `DEAD`/`DIR` 事件未匹配且
  `coverable_elsewhere=false`。
- 9 个结构错误用例分别命中各自预期错误码，且不产生正常结果。

> 性能数字为上述机器的实测值；不同硬件会有差异，但算法为多项式复杂度，
> 在 120x120 规模下远低于测试设定的 5 秒上限。
